COURSE CONCEPTS

Where the syllabus appears in this project

Big data and storage

The CSV is structured data stored as a local file. Its volume is intentionally small; HDFS, replication, sharding, and distributed storage are architecture concepts for a future scale-out version.

Hadoop and MapReduce

The semester lab groups mapper outputs by semester and reduces them into counts, averages, and risk rates. It teaches batch processing and key-based aggregation, but runs sequentially on this computer.

Hive and HiveQL

The grouped output is equivalent to a SQL aggregation. A Hive version could query a table partitioned by semester; Hive itself is not required or running in this local Flask demo.

SELECT semester, COUNT(*) AS students, AVG(overall_average) AS mean_mark FROM student_performance GROUP BY semester;

NoSQL and the CAP theorem

A future distributed student event store could use a NoSQL database for flexible records. Under a network partition, CAP describes the tradeoff between consistency and availability; this single-machine CSV app does not implement a distributed database.

HDFS architecture and replication

In HDFS, the NameNode tracks file metadata and DataNodes store file blocks, typically with replicated copies for fault tolerance. This project reads one local CSV, so HDFS storage and replication are architectural extensions, not active features.

Analytics with R

The existing model comparison, fairness metrics, and SHAP explanations are analytics work. Similar exploratory summaries and graphs can be reproduced in R; the web app currently uses Python.
